# CHANGELOG

## Unreleased

### Added

- **`reload` over `--cdp`**: the verb used to answer "reload is not supported over --cdp yet", which meant no benchmark could ever prove that a state change PERSISTED — persistence is only provable by destroying the page's memory first, and every scenario runs `--transport cdp`. It now issues `Page.reload` and blocks until `Page.loadEventFired`, deliberately not a re-navigate of the same URL: a repeat navigate can be served as a same-document navigation that leaves the page's in-memory JS alive, which would make "this survived a reload" vacuously true. Pinned by `internal/cdp/nav_reload_test.go` (the verb, and that it actually waits) (`htrcli/internal/cdp/nav.go`, `htrcli/internal/commands/cdp_exec.go`, `htrcli/internal/commands/navigate.go`, `skills/htrcli/SKILL.md`)
- **Benchmark captures now expand inside expectations**: `"capture": {"name": "..."}` values substitute into `stdoutContains`, `stdoutNotContains` and `jsonPath.equals` as well as argv, so a scenario can assert that a record opened on the id it just captured instead of hard-coding it. Captures shadow env vars in both places; an unresolved name stays literal and fails the step (`htrcli/internal/commands/bench_run.go`, `bench_capture_test.go`)
- **New benchmark scenarios S17–S20**: thread replies (B12a), support ticket create→update (B17), HR leave request (B19) and social post scheduling (B15) — each with a local fixture page and an offline-proxy scenario, plus `make bench-messaging` (S15+S17), `bench-tickets`, `bench-leave` and `bench-social`. S18 is the first scenario to reuse a captured id as a SELECTOR and to assert on it; S19 proves a computed inclusive day count (a weekend-spanning week must be 7, not 6 and not 5) and a balance that moves 14 → 7 → 14 across a request and a cancellation; S20 proves a hard 280-character cap with an ACCEPTED 280-character post (a counter-only assertion let a `>=` off-by-one in the validator survive, caught by mutation testing), refuses past and exactly-now scheduling against a fixed demo clock, and reschedules in place without duplicating. Fixtures live under `docs/benchmarks/fixtures/` (`social.html`, `leave.html`, `ticket.html`, `messaging.html`) with scenarios `s17`–`s20` (`Makefile`, `CLAUDE.md`, `TODO.md`, `docs/benchmarks/`, `skills/htrcli/SKILL.md`)
- **`expandBenchRef` stops `os.Expand` rewriting currency**: `$` references now require a shell-style identifier (`${name}`/`$name`, name starts with a letter or underscore), so `"$4,760.50"` stays literal instead of becoming `"${4},760.50"` once any capture exists. An unknown name keeps its original form (`${x}` stays `${x}`) so a typo fails as an obvious mismatch (`htrcli/internal/commands/bench_run.go`, `bench_expect_vars_test.go`)
- **New benchmark scenarios S21 (survey) and S22 (finance)**: B20 completes a three-page survey — per-question/per-row gates, Back restoring radio+select from the page's model, multi-select add/remove, a 10-char boundary (9 refused/10 accepted), second submit refused, confirmation + response list survive reload — and B18 proves a read-only statement — current vs available balance, period filter moving rows/total but never the balance, running balance reconciling with the header, account-scoped reads, and a live access log proving no write. Both offline-proxied against local fixtures (`fixtures/survey.html`, `fixtures/finance.html`) via `make bench-survey` / `make bench-finance` (`Makefile`, `CLAUDE.md`, `TODO.md`, `docs/benchmarks/office-task-benchmark.md`, `skills/htrcli/SKILL.md`)
- **`extract list --visible` and `||` field alternatives**: a live B01 run against Gmail returned 87 rows for 37 conversations — the SPA leaves the previous view in the DOM, and 50 of those rows were hidden (36 of them READ, so an `is:unread` search produced wrong-folder rows). `--visible` drops items that `checkVisibility` reports as hidden (Chrome 105+, Firefox 125+) and ERRORS when a host lacks it, rather than silently returning hidden rows as if the list had been filtered. Field selectors now accept `||` alternatives (`sender:span.yP||span.zF`, subject `span.bog||span.bqe`) with the first NON-EMPTY value winning, which is what live Gmail needs because its class names vary by read/unread state; `||` was chosen over `|` because `|` is live CSS (`[lang|=en]`), and the splitter is quote-aware so `[title="a||b"]` is not torn apart. Verified end-to-end over CDP against a probe page (3 rows with one inside `display:none`: 3 without the flag, 2 with it). The help text now explains the `@<css>@<attr>` form and both flags. Live Gmail re-check is pending an extension reload (`src/contentScript/extractData.ts`, `commandExecutor.ts`, `htrcli/internal/commands/extract.go`, `htrcli/internal/cdp/bundle/htrcli-dom.js`, `skills/htrcli/SKILL.md`)
- **New benchmark scenario S23 (re-order)**: B16 re-orders the most recent order and captures the new order number, proving that a re-order is not a copy — quantities carry over from the old order while prices come from today's catalogue (the pen pack is $7.25 today against $6.00 paid, so a fixture whose price never moved could not tell the two apart), the discontinued line stays visible in the cart but is excluded from the subtotal and absent from the review page, shipping makes the grand total differ from the subtotal, checkout gates address then payment one field at a time, and the new order gets a fresh id with the source row left byte-for-byte unchanged. Safety is asserted rather than assumed: the adjacent "Buy again (1-click)" decoy is proven reachable yet the audit log records zero 1-click entries, no new-card form is opened, and the order is then cancelled through a two-step confirmation that survives a reload. 13 mutants caught, including reorder-mutates-the-source-order and reorder-reuses-the-source-id (`docs/benchmarks/fixtures/store.html`, `docs/benchmarks/scenarios/s23-store-fixture.json`, `Makefile`, `CLAUDE.md`, `TODO.md`, `docs/benchmarks/office-task-benchmark.md`)

- **Middle-click a tab in the side panel's Connected Tabs list to close it**: the browser's native middle-click behavior is suppressed on the tab row (`onMouseDown` preventDefault stops the autoscroll/paste fallback), and `auxclick` with `button === 1` calls `chrome.tabs.remove` then refreshes the list. The tab row's tooltip now reads "Switch to this tab (middle-click to close)" for discoverability (`src/sidepanel/components/ConnectedTabs.tsx`)
- **Connected Tabs now sorts by actual browser tab position**: `getReadyTabsInfo`/`getTabsInfo` include `chrome.tabs.Tab.index`, and the panel sorts by it on every refresh and sync, so the list matches the browser's tab strip order instead of connection order (`src/background/index.ts`, `src/sidepanel/components/ConnectedTabs.tsx`)
- **`htrcli --cdp pick <selector> <text>`**: chooses an option in a custom combobox (react-select, async autocomplete) or a native `<select>`. Focuses the input without a visibility wait (react-select's 2px input), opens with a trusted `ArrowDown`, types with `Input.insertText`, polls up to 3s for `role=option` entries (listbox from `aria-controls`/`aria-owns` first), clicks the best match with a trusted mouse click (exact > prefix > contains; a tie is an error), and verifies the displayed value. Failures list up to 15 available options. For `<select>` the text is resolved to an option value first, because the existing `select` action assigns `.value` directly and silently selects nothing when given a visible label (`htrcli/internal/cdp/pick.go`, `htrcli/internal/cdp/formkit.js`, `htrcli/internal/commands/pick.go`)
- **`htrcli --cdp fill-form '<json>' | --file f.json`**: fills a whole form in one CDP session (ordered object or `[{selector, value}]`): text/textarea, `<select>`, checkbox, radio, combobox/react-select (via `pick`), file inputs (`DOM.setFileInputFiles` by object id), `null` skips. Every field is attempted even after a failure, then read back into a `Selector / Requested / Actual / Status` table; exits non-zero on any `FAILED`/`MISMATCH` (`htrcli/internal/cdp/fillform.go`, `htrcli/internal/commands/fillform.go`)
- **Global `--frame <css>` for same-origin iframes over `--cdp`**: `find`, `fill`, `type`, `check`, `uncheck`, `select`, `click`, `dblclick`, `value`, `text`, `attr`, `html`, `pick` and `fill-form` run inside the iframe (every scoped call is a `Runtime.evaluate` in the frame's main-world execution context — CSP-exempt, so frames served without `'unsafe-eval'` work; trusted clicks offset by the iframe's rect, border and padding). Every other verb, the extension transport, `@eN` refs, `xy=` and `find --ref` reject `--frame` explicitly; a cross-origin frame fails with a hint to `htrcli --cdp open <src>` (`htrcli/internal/cdp/frame.go`, `htrcli/internal/cdp/dom.go`, `htrcli/internal/cdp/input.go`, `htrcli/internal/cdp/session.go`, `htrcli/internal/commands/root.go`, `htrcli/internal/commands/cdp_exec.go`). Integration tests against headless Chrome: `TestCDPPick`, `TestCDPFrame`, `TestCDPFillForm` (`htrcli/internal/cdp/forms_integration_test.go`); browser setup moved into the shared `startIntegrationBrowser` helper
- **`htrcli tabs new <url>` / `tabs close <id>`**: opens a URL in a new (non-activated) tab and closes a tab by ID. Both run in the extension's **background worker** over the tab-less `POST /api/background/command` route, so neither needs another connected page — they work when only `chrome://` pages are open. `tabs close` resolves the ID against the connected http(s) tabs and then addresses the owning browser, so a tab must be connected before it can be closed. The new tab is deliberately not activated, so later commands without `--tab` keep targeting the current tab. A closed tab now sends an `unregister` message, which the daemon uses to remove it from the registry instead of routing to a dead ID and failing as "Invalid tab ID" (`htrcli/internal/commands/tabs.go`, `htrcli/internal/cdp/tabs.go`, `htrcli/internal/host/bridge.go`, `htrcli/internal/api/client.go`, `src/background/tabActions.ts`, `src/background/nativeHost.ts`, `src/background/index.ts`, `src/types/commands.ts`, `htrcli/README.md`, `skills/htrcli/SKILL.md`)
- **`--browser chrome|firefox` on the `tabs` subcommands, and strict `--browser` for tab-routed commands**: each browser numbers its own tabs, so the same native tab ID can exist in Chrome and Firefox at once. `--tab <id> --browser chrome` now *requires* the tab to belong to that browser and fails otherwise; without `--browser`, ownership resolves deterministically to the earliest-connected browser (`findOwnerIn`/`earliestConn`, replacing Go's randomised map iteration). The `tabs list/list --browser/get/new/close` flag is a separate, strict filter that never falls back to the other browser, and `--json` output carries `browser` (`htrcli/internal/commands/tabs.go`, `htrcli/internal/host/daemon.go`, `htrcli/internal/host/server.go`, `htrcli/internal/api/client.go`, `htrcli/README.md`, `skills/htrcli/SKILL.md`)
- **`htrcli --version` prints the build version**: `make htrcli-build`, `htrcli-build-all`, `htrcli-build-linux`, `htrcli install` and `.goreleaser.yml` stamp `commands.Version` through `-ldflags -X`, so a released binary reports the `git describe` value (bare, on stdout, for direct caller comparison) and an unversioned build reports `dev` (`Makefile`, `htrcli/Makefile`, `htrcli/.goreleaser.yml`, `htrcli/internal/commands/root.go`, `htrcli/README.md`)

- **`console read|watch` and `network read|watch|wait` now work over `--cdp`** (previously `errUnsupportedCDP`, so a model driving a form could not confirm a submission). With no daemon buffer, each verb reads what the page still holds or streams for the command's duration: `console read` collects V8's replayed console messages and uncaught exceptions on `Runtime.enable`; `console watch` streams new ones; `network read` lists completed requests from the page's Performance API (url, status, initiator type, duration, size — **no method, no bodies**); `network watch`/`wait` attach `Network.enable` and report method/status/url for requests completing after attach, with the extension path's `--url` glob and `--status` filter. `--since` is rejected over `--cdp` (no stable cursor across invocations), and each verb prints its limits to stderr or in `--json` (`transport`/`source`/`limitations`). Unknown methods now print as `—` instead of a blank column (`htrcli/internal/cdp/console.go`, `htrcli/internal/cdp/netlog.go`, `htrcli/internal/cdp/events.go`, `htrcli/internal/commands/events_cdp.go`, `htrcli/internal/commands/console.go`, `htrcli/internal/commands/network.go`, `htrcli/README.md`, `SPEC_HTRCLI.md`, `skills/htrcli/SKILL.md`)

- **Session recording over htrcli, working on Chrome AND Firefox**: the extension's own recorder (interaction steps + screenshots + annotations, persisted in IndexedDB) is now drivable remotely via a new `htrcli recordings` verb — `start [--title] [--audio]`, `stop`, `status`, `list [--limit] [--offset]`, `get <id> [--with-screenshots] [--output]`, `export <id> <file>`, `delete <id>`. This is distinct from `htrcli record`, which captures page **video** via CDP + ffmpeg and stays Chrome-only: the new actions need no `chrome.debugger`, so they work identically on both browsers, and `--cdp` is rejected with an explicit error. `get` strips base64 screenshots by default and reports `mediaStripped`; `export` always includes them. `list` is sorted newest-first and paginated, and audio defaults OFF so a remote caller can never silently open the microphone. **`get --with-screenshots` / `export` pre-check the step count and refuse over ~120 steps**, because the hydrated session must fit in one native-messaging frame capped at 64 MiB, and an over-cap frame is treated as a protocol error that tears down the connection (`src/background/recordingCommands.ts`, `src/background/nativeHost.ts`, `src/background/index.ts`, `src/types/commands.ts`, `src/types/recording.ts`, `htrcli/internal/commands/recordings.go`, `htrcli/internal/api/types.go`, `skills/htrcli/SKILL.md`, `htrcli/README.md`, `CLAUDE.md`)

Existing `.json` invocations are unchanged, and an unrecognised extension falls back to JSON. ### Fixed

- **Connected Tabs list is responsive in the side panel on Chrome and Firefox**: with many tabs the list grew to its full height and squeezed the Timeline out, pushing the Export panel past the bottom of the fixed-height panel. `.ct-list` now caps at `40vh` and scrolls internally, so the rest of the panel keeps its space (`src/sidepanel/components/ConnectedTabs.css`)
- **`htrcli tabs new` / `tabs close` always timed out (30s) on both Chrome and Firefox**: the daemon wrote tab-less background commands with `TabID: 0`, but `NativeMessage.TabID` was `json:"tabId,omitempty"`, so the key was dropped from the wire. The extension routes tab-less `openTab`/`closeTab` with `tabId === 0`; it received `undefined`, fell through to the per-tab content-script path for a tab that does not exist, and never answered. Recording commands were unaffected because they do not check `tabId`. `tabId` is no longer omitempty, and the existing test now asserts the literal `"tabId":0` on the wire (`htrcli/internal/host/native.go`, `htrcli/internal/host/daemon_background_internal_test.go`)
- **CDP selector drags always failed with `Unknown action: undefined`**: the page-side drag resolver called the DOM bundle with capitalised command keys (`{ID, Action, Target}`) while the bundle destructures `{action, target}`. Keys are lowercase now, and the batched-resolve test pins the call shape (`htrcli/internal/cdp/input.go`; `TestDragResolvesBothEndpointsInOnePass`, integration `TestCDPDrag`)
- **CDP drag fit-scroll re-check inspected stale points**: after the one fit-scroll, the "still outside the viewport" check looked at the endpoints captured BEFORE the scroll, so every drag that needed a fit-scroll failed even when the scroll had worked. The check now re-derives the prepared points from the re-read positions (`htrcli/internal/cdp/input.go`)
- **`@eN` drag endpoints were pixels captured before the other endpoint scrolled**: a ref was converted to viewport coordinates up front (`DOM.getBoxModel` + `Page.getLayoutMetrics`), then the selector endpoint's `prepareClick` centred the page and the press landed where the ref USED to be — the exact stale-coordinate bug the batched resolver fixes, re-introduced for refs; an off-screen ref was never scrolled into view at all. Refs now travel to the page-side resolver as element handles (`DOM.resolveNode` + `Runtime.callFunctionOn`) and are scrolled and re-read together with the other endpoint; `ResolveBackendNodeCoordinates` is gone (`htrcli/internal/cdp/input.go`, `htrcli/internal/commands/cdp_exec.go`, `htrcli/internal/cdp/elementref.go`; `TestDragRefEndpointsTravelAsElementHandles`, `TestRunDragCDPPassesPersistentRefsAsElementHandles`)
- **Mixed `xy=` + selector drags under `--frame` offset the literal as if it were frame-local**: only prepared (selector) points are now converted to top-viewport coordinates; a literal is already top-viewport pixels (`htrcli/internal/cdp/input.go`)
- **`--frame` DOM bundle install was subject to the frame's CSP**: `contentWindow.eval(bundle)` is blocked by a frame served with `script-src` lacking `'unsafe-eval'`, failing every frame-scoped verb. The frame's main-world execution context is now resolved once (`DOM.describeNode` frameId + `Runtime.enable` context replay) and every scoped call — install included — runs via `Runtime.evaluate` with that `contextId`, which is CSP-exempt; a context invalidated by a frame navigation is re-resolved once. The integration pages are now served with `script-src 'self' 'unsafe-inline'` to keep this pinned (`htrcli/internal/cdp/frame.go`, `htrcli/internal/cdp/session.go`; `TestExecDOMInFrameColdPath`, `TestCDPFrame`)
- **A script exception while resolving an element handle was reported as "no element matches"**: `evaluateObject` returned the decoded `exceptionDetails` AS the result, so the exception text was swallowed. It is now an error carrying the exception description (`htrcli/internal/cdp/frame.go`; `TestEvaluateObjectReportsExceptions`)
- **`pick` polled an ambiguous combobox list until the 3 s deadline**: a tie between equally ranked options is now reported as soon as the list is unchanged across two polls, like a weak match is accepted (`htrcli/internal/cdp/pick.go`; `TestPickSettledReportsTieOnce`)
- **Console source attribution dropped `<anonymous>` frames and scheme-stripped page frames**: a stack whose page frame is `<anonymous>:1:5` (DevTools input, `new Function`) reported no source, and a scheme-stripped page frame (`vendor/polyfill.js:10`) aborted the search even when the extension's own path was known. Both are now reported; a scheme-stripped frame with the own path UNKNOWN still aborts, since it could be the wrapper (`src/contentScript/stackSource.ts`)

- **Drag and console source fixes**: `--cdp drag` fit-scrolls endpoints that sit inside nested scroll containers, not only the window (`htrcli/internal/cdp/input.go`, `htrcli/internal/cdp/frame.go`). The extension's selector drag reads both endpoints only after both are scrolled, so the press no longer lands where the source used to be (`src/contentScript/commandExecutor.ts`). A page frame whose file name matches the extension's script (e.g. `index.js`) is no longer dropped from console source attribution (`src/contentScript/stackSource.ts`)
- **`--frame` recovers from more stale-context errors**: a frame navigation that surfaces as "Execution context was destroyed" or "Cannot find default execution context" re-resolves the frame context once, as "Cannot find context with specified id" already did (`htrcli/internal/cdp/frame.go`)
- **`--cdp network watch` records a redirect hop whose request began before attach**: the hop is reported from the redirect response instead of being lost (`htrcli/internal/cdp/netlog.go`)
- **`--cdp pick` no longer reads options from the whole page**: when a combobox has no `aria-controls`/`aria-owns` link and no open listbox in its container, `pick` fails with a clear error instead of matching options elsewhere (`htrcli/internal/cdp/formkit.js`)
- **`extract table` header inference never drops a data row** (`extractData.ts`): a row of `<td>` cells is now always DATA — previously the first row was silently consumed as an implied header, turning its first cell into a column name and losing its values. Caught by the offline Sheets benchmark scenario S06 (`extract table "#grid"` on `docs/benchmarks/fixtures/sheets.html`, expected `rowCount: 3`, was `2`), which now PASSES; the smoke scenario S01 (which has a real `<thead>`) and Docs/Calendar remain unaffected. (`extractData.ts`, `extractData.test.ts`, `htrcli/internal/cdp/bundle/htrcli-dom.js`)

### Changed

- **`collect --ref` refs go stale when scrolling a recycling virtualizer**: `collectAll` mints each `@eN` ref at harvest time via the `onRow` hook while the node is live; once collect scrolls the list, the harvested nodes detach, so a ref no longer resolves ("stale ref") and callers must use it immediately or re-harvest/find again after scrolling — the earlier "no longer yields a stale ref" claim only held at harvest time. Pinned by a new regression test that scrolls a recycling list and asserts every harvested node is detached (`src/contentScript/collectList.test.ts`, `src/contentScript/collectList.ts`, `TODO.md`)
- **htrcli skill: navigate by clicking, not by URL**: the CDP quick rules now instruct the agent to follow on-page links/buttons (via `find` + `click`) instead of constructing URLs with `open`, because clicking runs the site's own navigation (SPA routing, referrer, state) while a typed URL can 404 or skip steps. `open` is reserved for the entry URL or when no on-page path exists. Rules renumbered 3–8 (`skills/htrcli/SKILL.md`)
- **One bundle install/retry path for every page-side helper**: the sentinel → install → retry-once loop that `ExecDOM`, the frame exec and the drag resolver each re-implemented is now `withBundle`, parameterised by the bundle (`DOM bundle`, `form kit`). `formkit.js` is installed once per realm as `window.__htrcliFormKit` and called by name — it was previously re-shipped and re-evaluated (~6 KB) on every `pick` poll and every `fill-form` field (`htrcli/internal/cdp/dom.go`, `htrcli/internal/cdp/pick.go`)
- **`network read` over `--cdp` ships Performance API fields verbatim**: no `|| 0` / `|| ""` defaults in the page-side expression; an absent or zero `responseStatus`/`transferSize` reaches Go as its zero value and is rendered as unknown by the existing `omitempty` tags (`htrcli/internal/cdp/netlog.go`)
- **CDP integration tests open their own `about:blank` target** (`Target.createTarget`) instead of attaching to whatever page a fresh profile opened first — recent Chrome opens `chrome://newtab`, and `Page.navigate` against that target can hang (`htrcli/internal/cdp/integration_test.go`, `htrcli/internal/cdp/events_integration_test.go`)

- **`fill-form` read-back could report `OK` for a field it never set**: the `<select>`/`combobox` comparison used `strings.Contains` against the raw request, so an empty request (`strings.Contains(x, "")` is always true), a substring of the displayed label, or a DIFFERENT option whose text happened to contain the request all passed. Read-back now compares exact normalized equality against what the fill VERIFIED it produced (`pickSelect`'s selected option text / `pickCombobox`'s displayed label), falling back to the request only when the fill already failed (that row is `FAILED` anyway). Text fields now apply the browser's own value sanitization to both sides — `<textarea>` line endings canonicalize to LF, `<input>` strips newlines — so a fill the browser itself rewrites is no longer a false `MISMATCH`; a fill the browser rejected (bad `number`/`date`) still is (`htrcli/internal/cdp/fillform.go`; cases in `TestCompareField`)
- **CDP drag pressed where the source USED to be**: `Drag` resolved each endpoint independently, and `prepareClick`'s unconditional `scrollIntoView(center)` for the destination moved the page between the two reads — so on any scrollable page the press landed at stale coordinates (and with `--frame`, a second `toTopViewport` scroll could invalidate the first point). Both endpoints are now resolved in ONE page-side pass (`dragPointsFn`: prepare both → re-read both centres without scrolling → one fit-scroll → re-read), converted to top-viewport coords in ONE `toTopViewportPts` call, and the drag errors clearly when source and destination cannot both be seen at once instead of dispatching at coordinates that moved (`htrcli/internal/cdp/input.go`, `htrcli/internal/cdp/frame.go`; test `TestDragResolvesBothEndpointsInOnePass`)
- **`--frame` clicks missed inside nested scroll containers and on scaled iframes**: `toTopViewport` only ran `window.scrollBy` (which cannot reach a nested `overflow` container) and mapped frame-local coordinates without accounting for `transform:scale`, then dispatched blind. It now scrolls every scrollable ancestor that clips a point, maps through the iframe's rendered-vs-layout ratio, and verifies each point with `document.elementFromPoint` — a point that lands on something other than the iframe is an error naming what is actually there rather than a silently wrong trusted click (`htrcli/internal/cdp/frame.go`; test `TestToTopViewportPts`)
- **`waitForActionableElement` re-scrolled a below-the-fold element on every 50 ms poll**: scrolling is a side effect but `check()` ran as a predicate on every poll and every DOM mutation, so a rendered-but-offscreen element was re-centered continuously, fighting any scroll the page or the user performed during the wait. The scroll now happens at most once per element per wait, and `check()` is side-effect free (`src/contentScript/elementFinder.ts`, rebuilt `htrcli/internal/cdp/bundle/htrcli-dom.js`; test in `elementFinder.test.ts`)
- **`network watch` emitted an entry with an empty URL and method**: `Network.loadingFailed` for a request never seen starting (it began before `Network.enable`) completed a synthesized empty in-flight record. It is now dropped exactly like the matching `loadingFinished` case, since a row with neither URL nor method is indistinguishable from a broken one (`htrcli/internal/cdp/netlog.go`; test in `netlog_test.go`)
- **One fewer round trip per DOM command, and a real cross-origin error for `fill-form` file uploads in a frame**: every `ExecDOM` call paid a separate `typeof` bundle probe before executing (2 evaluates steady state). The check is now folded into the exec expression behind a `__htrcliNeedBundle` sentinel — install once, retry once, self-heal after navigation — so steady state is 1 evaluate for both the top realm and `--frame`. `elementObjectID` no longer builds its own frame root (whose cross-origin failure was a cryptic `Cannot read properties of null`); it splices the shared `frameLookupJS`, so `fill-form` with `type=file` inside a cross-origin `--frame` now gets the same `open <src>` hint as every other frame verb (`htrcli/internal/cdp/dom.go`, `htrcli/internal/cdp/frame.go`; tests `TestExecDOMInstallsBundleOnce`, `TestExecDOMInFrameColdPath`, `TestElementLookupExpr`)
- **`--frame` validation no longer matches leaf command names against a hand-kept allowlist**: a subcommand whose leaf name collided with a frame-aware verb would have been silently accepted (acting on the top page), and a newly added frame-aware verb silently rejected. The frame-aware set now lives as a cobra annotation ON each command (`FrameAwareAnnotations()`), validation walks `cmd → parent`, and the rejection message is generated from the annotations so it cannot drift from them (`htrcli/internal/commands/root.go` + the 14 annotated verbs; drift test in `TestValidateFrameFlag`)

- **`pick` falsely failing (or falsely passing) on pages with smooth scrolling**: on the live Greenhouse form the first `pick` on a cold page reported `the combobox shows ""`. Cause: `html{scroll-behavior:smooth}` made `scrollIntoView` animate, so the option's coordinates were read mid-scroll and the trusted click landed outside the viewport. `pick` now scrolls with `behavior: "instant"` and refuses to click a point outside the viewport. The verification also reads only the input's own `.select__value-container`, never the leftover query text in the input (which could report a selection that never happened); it polls up to 2s and the error names the value read, the element it was read from, and the click point (`htrcli/internal/cdp/formkit.js`, `htrcli/internal/cdp/pick.go`, `htrcli/internal/cdp/frame.go`; regression test `TestCDPPickSmoothScrollDelayedRender`)
- **Clicks missing on pages with smooth scrolling**: every `scrollIntoView` in the content script / CDP DOM bundle used `behavior: "auto"`, which honours `html{scroll-behavior:smooth}`, so coordinates were read mid-animation and a trusted click could land outside the viewport. They now use `behavior: "instant"` (`src/contentScript/commandExecutor.ts`, `src/contentScript/elementFinder.ts`, rebuilt `htrcli/internal/cdp/bundle/htrcli-dom.js`).
- **`not visible` for elements below the fold**: `waitForActionableElement` now scrolls a rendered-but-offscreen element into view before judging visibility (`src/contentScript/elementFinder.ts`; tests in `elementFinder.test.ts`).
- **The popup could silently destroy an in-flight recording**: the toolbar popup ignored `response.success` (the background reports failures in the response *body*, not via `runtime.lastError`), so a failed start rendered as a normal idle screen; and because it only polled while already recording, it never learned that htrcli or the side panel had started a session, leaving a live "Start recording" button. The popup also checks `success` and listens for `RECORDING_STARTED`/`RECORDING_STOPPED` (`src/background/index.ts`, `src/background/recordingCommands.ts`, `src/popup/Popup.tsx`)
- **`recordings delete` no longer resurrects the live session**: deleting the in-flight session reported success and made it vanish from `list`, but the next `stop` rewrote the row with an unconditional put, so it silently reappeared. It is now refused, with the reason (`src/background/recordingCommands.ts`)
- **Side panel no longer goes stale on a remote start/stop**: `startRecording`/`stopRecording` never broadcast `RECORDING_STARTED`/`RECORDING_STOPPED` (the message types existed but were unused), so the panel only stayed in sync when *it* initiated the action. A recording started or stopped from htrcli — or from the toolbar popup — left an open side panel showing stale state. Both functions now broadcast, the side panel listens for `RECORDING_STARTED` and dispatches straight from the payload instead of round-tripping `GET_RECORDING_STATE`, and the tab-close auto-stop no longer double-broadcasts (`src/background/index.ts`, `src/sidepanel/context/RecordingContext.tsx`, `src/types/recording.ts`)

- **`browser start` no longer hangs after a crashed Chrome**: a stale profile `SingletonLock` (owner pid dead — crash, reboot, SIGKILL) made every start wait 15s and fail while leaving an orphaned Chrome and a stale `browser.json`. Launch now removes `SingletonLock`/`SingletonSocket`/`SingletonCookie` when their pid is gone, kills the spawned Chrome if the debugging port never answers, and rewrites `browser.json` instead of reporting a dead pid when the port was already alive (`htrcli/internal/cdp/launch.go`, `htrcli/internal/cdp/launch_test.go`)
- **`browser stop` can stop a browser whose recorded PID went stale**: when the debugging port already answers but the recorded PID (`browser.json` or a context in `contexts.json`) is dead (or `0`), launch now adopts the real listener PID — `lsof` on Unix, `netstat -ano` on Windows — instead of persisting `0`, which failed `stop`'s `chrome-profile` command-line check and left that Chrome unstoppable; if the listener cannot be identified, launch errors out rather than writing a meaningless PID, and a failed registry write no longer tears down an adopted (not htrcli-launched) browser. ### Changed

- **`htrcli recordings` no longer needs an open page.** Recording actions moved from the tab-routed `POST /api/command` (where a nil tab was resolved by the daemon through `FirstTabID`) to a new tab-less route, `POST /api/background/command`, which selects a browser **connection** instead of a tab. Previously a recording could only be driven when at least one `http/https` tab with an active content script had reported in, so it failed from a `chrome://` page, a settings page, a headless browser, or a browser sitting entirely on the new-tab screen. The new route needs only a connected extension relay, and answers `404 no browser connected` otherwise
- **`FirstTabID()` is now deterministic.** It previously returned whichever tab Go's randomised map iteration happened to yield, so repeated lookups could resolve to different browsers; it now returns a tab from the earliest-connected connection (lowest `seq`), then the lowest tab ID on it. **This changes which browser every nil-tab route reaches**, not just recordings — all four `FirstTabID` callers in `htrcli/internal/host/server.go` are affected. No test expectation had to change: the one pre-existing assertion was single-connection and never luck-dependent
- **New `--browser chrome|firefox` flag** for tab-less commands. It is an **advisory hint, not a selector**: the daemon prefers a relay that announced that browser and otherwise falls back to the earliest-connected relay, so a hint naming a profile that is not running still returns an answer. `recordings list` prints `Answered by: <browser>` so the answering profile is always visible. An unrecognised value is a loud CLI error rather than being ignored, so a typo cannot masquerade as a working first-wins call
- **The extension now announces its browser** to the daemon with an `identify` message once per connection (after the daemon's greeting confirms the link, and again on every reconnect). The daemon validates it against the browsers it knows and ignores empty/unrecognised values, because a stored value becomes selectable as a command target. Backwards compatible in both directions: an old daemon ignores the unknown message type, and an old extension never sends it and stays reachable through the no-hint path
- **Command results now decode in a single pass.** `api.Client.ExecuteCommandInto` and its tab-less counterpart `ExecuteBackgroundCommandInto` decode a response's `data` field straight into the caller's type via a `json.RawMessage` envelope, instead of the previous `ExecuteCommand` path that materialised the payload twice — once as `map[string]any` inside `ApiResponse`, then again as bytes via `json.Marshal`. For a recording exported with screenshots that is ~48 MB of base64 held two extra times over. `ExecuteCommand` itself is deliberately unchanged, since every other command depends on it (`htrcli/internal/api/client.go`)
- **The recording-export ZIP bundle is now a pinned cross-boundary contract.** `shared/recording-export-contract.json` is the single source of truth for the bundle layout (entry names, directory names, compression, the `step_%d.png` / `annotation_%d.png` path patterns). Neither producer reads it at runtime — it is a contract, and two tests bind their respective producer to it: `src/utils/exportZip.contract.test.ts` (extension) and `htrcli/internal/commands/recordings_export_test.go` (CLI), so changing one producer's output fails its test until the contract is updated too and the two cannot drift silently. To make the extension side assertable at all, `exportToZip` was split into a pure `buildRecordingZip` that returns the `JSZip` and a thin wrapper that triggers the download (`shared/recording-export-contract.json`, `src/utils/exportZip.ts`, `htrcli/internal/commands/recordings_export.go`)
